# 维护项目背景

让后续任务能从仓库恢复可靠、简洁的项目事实与状态。只保存影响未来工作的结论、必要理由和证据摘要；没有有效增量时不修改文件。

## 先读取现场

- 以本 skill 所在仓库为目标，确认仓库根目录，读取适用的 `AGENTS.md` 和根目录 `README.md`。下文路径均相对仓库根目录；文件若迁移，按实时索引定位，不另建重复副本。
- 检查 `git status --short` 及目标文件已有差异。工作区中的最新内容（包括用户未提交改动）是维护基线；不得用 HEAD、远端、历史聊天、AI 记忆或临时目录覆盖它。
- 按 `01 → 02 → 03 → 04` 顺序读取相关 Context；涉及跨文件同步时读取所有受影响文件。项目角色或状态变化时读取 `projects/README.md`；涉及长期选择时读取 `docs/decisions/README.md` 和相关既有 Decision。
- skill 只定义维护方法，不保存当前学习阶段、项目版本、技术优先级或完成状态。这些均从实时仓库和本次明确的新信息中判断。

## 筛选信息与依据

将候选增量区分为以下类别；可用简短行内说明，无需给所有旧内容重新加标签。

| 类别 | 写入依据与边界 |
| --- | --- |
| 项目事实 | 标明事实来源和适用范围。仓库原有记录只是本次基线，不等于本次重新验证；用户提供的运行结果应写为用户提供，不能声称亲自运行。 |
| 用户已确认 | 记录明确决定及必要理由；确认要做某事表示计划，不能改写成已经完成。 |
| 实践证据 | 摘要记录实际执行对象、结果及验证范围；有现成路径、报告或提交标识时保留必要引用，不编造证据和日期。 |
| 待确认建议 | AI 推断或建议不得写入已确认状态、路线决策或正式 Decision。仅当影响当前推进且需要用户裁决时，在现有 Pending / Open Items 中列为待确认问题，否则只在回复中提出。 |

只保留目标、优先级、学习状态、任务切换、稳定约束、工程项目关系或长期决策的有效变化。过滤完整讨论、教程、代码示例、课程转写、临时 Debug 过程、一次性错误及无后续影响的环境细节。知识正文属于 Obsidian，真实工程代码属于独立工程仓库；本 skill 不代为整理或复制它们。

## 检查重复与冲突

- 在受影响文件中查找同一主题、旧名称、状态和关联待办。已有等价结论时更新原条目或引用，不重复追加。
- 区分历史与现状、局部验收与整体完成、计划与实施，以及不同项目或不同运行环境；这些差异不一定是冲突。
- 新信息与旧记录冲突时，列明冲突和依据。用户最新明确决定可替代旧计划；实际证据只能证明其验证范围，不能替用户改变目标或优先级。
- 对有明确依据的更新，同步修正相关当前摘要、路线、进度、待办和索引，简要说明旧结论被何种新决定或证据取代。历史事件保留其时间语义，不伪装成仍有效的当前状态。
- 无法判断哪条有效时，保留争议内容，提出具体待确认问题，只继续无争议的更新。不要仅凭文件更新时间较新、条目靠后或措辞更确定就判定胜出。
- 发现与本次无关的历史矛盾时简要报告，不趁机全面清理或重写 Context。

## 按职责落位

只修改本次变化实际影响的文件；跨文件保留各自所需的摘要，不复制整段内容。

| 文件 | 维护内容 |
| --- | --- |
| `context/01-Profile-and-Goals.md` | 稳定背景、职业目标、长期约束和技术主线；短期进度不在此累积。 |
| `context/02-Learning-Roadmap.md` | 路线、优先级、阶段目标、依赖顺序和已确认技术决策；同步受影响的里程碑与待决事项。 |
| `context/03-Learning-Progress.md` | 学习状态、完成证据、待实践或复习项、下一步；同一主题的概览、进行中与待办保持一致。 |
| `context/04-Current-Task.md` | 恢复当前工作所需的 Active Task、Goal、Confirmed State、Open Items、Next Action；任务切换时清理失效短期项，保留仍有效的并行任务。必要长期结论先落入对应文件，避免把这里变成流水账。 |
| `projects/README.md` | 独立项目的定位、仓库或路径、关系及状态；只有确知的地址才写成链接，不复制工程 README 或代码。 |
| `docs/decisions/` | 经用户明确确认或项目实践验证、且具有长期工程影响的选择。遵循该目录实时范围和模板；已有决策则更新或关联，简单路线变化不必单独建文档。保留依据、理由和后果，明确被替代关系。 |

根目录索引仅在结构或导航真实变化时更新；不要改无关版本标记、仓库协议或配置。以各文件现有结构为准，实质变更时更新已有 Last Updated 字段；事件日期与编辑日期分别处理，不为无变化文件刷新日期。

## 学习状态的证据门槛

- 状态词汇以实时 `AGENTS.md` 为准；当前允许：`待学习`、`学习中`、`基础完成`、`需要实践`、`需要复习`、`阶段完成`、`暂缓`。
- `待确认` 表示信息置信度或开放问题，不作为新的学习状态。若既有条目如此使用，先核实状态依据，不机械改成 `待学习`。
- 讨论过、看过课程、读过文档或收到 AI 示例，都不证明掌握。存在明确学习、实践、运行、验收或用户确认依据后，才按对应范围调整状态。
- 运行通过不自动等于理解验收通过；一个子项完成不等于整阶段完成，旧项目通过不等于新项目通过，环境就绪不等于业务实践完成。项目若要求用户理解确认后进入下一阶段，保留该门槛。
- 不用“已掌握”扩大有限证据。证据不足时保留可支持的状态，说明缺少什么；既有完成项没有新反证时不因本次未重新验证而降级。

## 修改与交付

- 在现有文本上做局部、可审阅的改动，保留不相关的未提交内容。写入前若发现并发变化，重新读取并合并；不能安全合并时只暂停冲突部分。
- 修改后复查差异：事实来源与确认程度准确、状态提升有依据、关联当前条目无矛盾、链接可定位、没有重复知识正文或超出范围的文件改动。再次输入同样信息应无需新增记录。
- 验证本 skill 时使用只读推演或隔离样本，不为测试而改真实 Context。
- 交付简要说明改了哪些文件、记录了什么结论及依据、未解决的冲突或待确认事项；若无有效增量，说明无需更新。除非用户另行明确要求，不暂存、提交或推送 Git。
